# Plan: Add miR-eCLIP example dataset to test suite

## Goal
Wire the new `example_mir_eCLIP` dataset (using `example_annotation_mouse_chr19`) into the
existing test suite (DAG test, config test, and full/crosslinks test), following the exact
pattern used for `example_eCLIP`, `example_iCLIP`, etc. Tests are expected to fail initially;
this is a scaffolding step, not a bug-fixing step.

## Inputs already present
- `example_data/example_mir_eCLIP/IP10_WT1_miR181_R1_001_chr19_1000reads.fastq.gz`
- `example_data/example_mir_eCLIP/IP11_WT2_miR181_R1_001_chr19_1000reads.fastq.gz`
- `example_data/example_annotation_mouse_chr19/annotation_mm10_chr19.fa`
- `example_data/example_annotation_mouse_chr19/annotation_mm10_chr19.gtf`

## Known gap (user to provide)
- `mir_genome_fasta`: a FASTA of mature microRNA sequences (e.g. from miRBase, matching
  "miR181"/mmu-mir-181 family) is required by the `miReCLIP` experiment type
  (`racoon_clip/workflow/Snakefile:1850`, rule `make_miR_index`). No such file currently
  exists in the repo. The user will add this file themselves at:
  `example_data/example_mir_eCLIP/mir181_mouse.fa` (placeholder path — user may rename;
  if the final filename differs the config will need a one-line path update).
  The config file will reference this path even though the file may not exist yet when
  the plan is executed; if it's missing, DAG/config/crosslinks tests are expected to fail
  at the `make_miR_index` rule, consistent with the expectation that these tests won't pass
  immediately.

## Steps

1. **Create config file**
   `example_data/example_mir_eCLIP/config_test_mir_eCLIP.yaml`, modeled on
   `example_data/example_eCLIP/config_test_eCLIP.yaml`, with:
   - `wdir: "./test/out_mir_eCLIP"`
   - `infiles`: both fastq.gz files (relative paths, space-separated)
   - `samples`: matching basenames (without `.fastq.gz`)
   - `experiment_type: "miReCLIP"`
   - `adapter_cycles: 2`, `adapter_trimming: True` (following eCLIP-like settings; may need
     adjustment once the pipeline runs and issues surface)
   - `genome_fasta` / `gtf`: pointing at `example_annotation_mouse_chr19/annotation_mm10_chr19.fa`
     / `.gtf`
   - `read_length: 45` (placeholder, matching other example configs; can be corrected during
     bug-fixing if reads are a different length)
   - `mir_genome_fasta`: path to the miR fasta the user will supply
   - `mir_starts_allowed: "0 1 2 3 4"` (per tutorial_mir.rst example)

2. **Register the new config in `tests/test_suite.py`**
   - Add `"example_data/example_mir_eCLIP/config_test_mir_eCLIP.yaml"` to
     `self.config_files` (used automatically by DAG tests and crosslinks/full tests).
   - Add a new tuple to `config_mappings` in `test_config_files()`:
     ```python
     ("example_data/example_mir_eCLIP/config_test_mir_eCLIP_updated.yaml",
      "tests/expected_output/out_mir_eCLIP/config_test_mir_eCLIP_expected.yaml"),
     ```
   - Do **not** add to `peaks_configs` in `test_all_peaks()` unless the user wants full-pipeline
     peak calling tested too (currently only eCLIP_ENCODE + iCLIP are peak-tested). Default:
     leave it out, matching "DRAG test, config test, and full test" request — full test in this
     codebase = DAG + config + crosslinks + peaks + fastqscreen, but crosslinks is the "DRAG"
     step for miR data; peaks calling is a separate optional step. Will flag this distinction
     to the user rather than assuming.

3. **Create expected-output scaffold**
   - Create directory `tests/expected_output/out_mir_eCLIP/`.
   - Since the pipeline is expected to fail/need bug fixes, we cannot yet generate a correct
     `config_test_mir_eCLIP_expected.yaml` by running the tool. Options:
     a. Leave the expected-output directory empty for now with a short placeholder note,
        letting the config test fail loudly (missing expected file) until bug-fixing produces
        a real "updated" config to snapshot.
     b. Hand-construct an expected config by reasoning through `Snakefile` config defaults
        (similar to `config_test_eCLIP_expected.yaml`), best-effort, to be corrected later.
     Default: **(a)** — do not fabricate expected output values; this keeps the config test
     failing for the right, informative reason ("expected file not found") rather than a
     misleading diff. This will be called out clearly when reporting results.

4. **Do not modify documentation** (per AGENTS.md) — will flag to user that
   `docs/tutorial_mir.rst` may need updates once the module works, but won't touch it.

5. **Validation after edits**
   - `bash -n` not applicable (Python), so instead run:
     - `python tests/test_suite.py test_light --no_clean` scoped mentally / or just the DAG
       generation for the new config via `racoon_clip peaks --cores 1 --dag --configfile ...`
       to confirm the new config is at least picked up (failure due to missing miR fasta is
       expected and acceptable).
   - Report the failure mode back to the user as the expected starting point for bug-fixing.
